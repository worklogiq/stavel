## Implemented mechanisms

PLAN asks the unanswered story choice, uses selected repository template bytes and pins the selected design/source hashes. Direct design-to-PLAN is allowed by default; the manifest records `design-selection` against the first explicit design baseline without claiming accepted review or requiring an exception. A repository can deliberately require review for substantial work; explicitly small scopes and a configured `none` policy remain direct paths. Provided actual review/exception records are retained and pinned. Separate slice files and a derived macro are rendered. The manifest reader refuses incomplete schemas, duplicate/unsafe destinations, dependency cycles, unknown prerequisites and artifacts outside their packet home. External prerequisites identify a completed canonical execution block by packet/slice identity; their file and actual evidence hashes are checked rather than treating an arbitrary existing file as successful delivery.

Execution-plan, execution-slice, macro and selected story roles now use the common resolved artifact definitions and shared template/section renderer. A new packet includes an actual execution-plan document registered as optional-backward-compatible `manifest.plan`, real source/design/slice/dependency indexes, each separate canonical slice block and one owned tracker block. Repository templates, standing section amendments and aligned inline story content retain their selected guidance through transitions and archival. Competing template status fields are removed while Mode/branch context remains; an unselected branch is labelled as such. Mandatory role omissions carry effective-source provenance, and applied kind/naming collisions refuse instead of ignoring configured choices. Rendering pins actual repository template/configuration/link inputs and validates links across the complete future output graph before writing.

The explicit one-time provisional packet migration accepts a batch of actual owner/slice/status/dependency/evidence mappings. It validates old `slice-id` and `execution-status` fields against those mappings, permits explicit active/partial normalization to in-progress, retains original bodies/IDs/paths and records original source hashes. It removes the obsolete status field and appends one canonical execution block. The original macro prose/table remains an identified historical snapshot while an owned derived tracker block is refreshed. The whole qualified slice graph must be acyclic even when packet-level relationships cycle. Completed mappings require existing proof/check/review sources; conversion does not infer completion or acceptance. Agent-mapped conversion carries the nondeterministic migration warning. Incomplete migrated external prerequisites remain visibly unready; a material result change still requires an explicit accepted proof binding rather than silent refresh.

Transitions retain check identities/descriptions and refuse omission or downgrade of a required check. Completion needs a meaningful result, actual existing evidence, passed required checks and an actual existing semantic-review record. Those sources are hash-bound and rechecked before dependency readiness or closure. These are structural/data prerequisites; they cannot establish that a claimed test actually ran or that a human/agent review was sound. The author and reviewer still own that judgment.

Archive refuses active packets and collisions. It moves the entire closed packet, including binary and hidden files, to the configured owner-relative mirror. Markdown links and packet-local evidence paths are rebased. Active inline/reference-style evidence links move under the historical heading. Archived slice/story metadata reflects actual complete/cancelled outcomes; mixed or cancelled trackers and unfinished attached historical documents become deprecated, preserving actual acceptance fields. The archived manifest retains original source paths/hashes in `archive.sourceHome` and `archive.sourceHashes`; current pins reflect only explicit mechanical relocation, link and lifecycle-metadata changes. Material changes to shared evidence remain discrepancies rather than automatic completion of any other packet.

The same concrete archive preview mechanically refreshes supported dependent packet manifests and canonical proof pins in dependency order, retaining old references/hashes in factual `referenceHistory` entries without new acceptance. Capability-owned work record/tracker references and supported decisions-topic source references are rebased while preserving actual lifecycle state and selected decision values. Current configuration homes, owner authority mappings, active amendment sources and unsupported/self-referential proof structures conservatively refuse before writes when they cannot be safely preserved. Arbitrary application JSON is untouched. Every read source and affected dependent record is hash-bound to the preview.

VIBE emits a proportional checkpoint containing the actual trigger, result/context, source references and next action. Reusing its identity refuses instead of overwriting the prior checkpoint.
