## Diagram inventory

List applicable context, component and critical-path diagrams. Include an ERD only for a data-bearing capability; record why a diagram is omitted.

## Context and components

Use reviewable diagrams to identify actual actors, boundaries and dependencies. Do not manufacture client/server/database layers.

## Critical path and data model

Describe the defining sequence, failure/recovery path and applicable entity relationships with ownership and compatibility constraints.

## Invariants and verification

Link the requirements and evidence that support each important invariant. Diagrams illustrate intent; they are not runtime evidence.
