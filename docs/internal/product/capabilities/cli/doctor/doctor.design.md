## Findings

Doctor resolves target policy early and runs packaged structural checks. It reports passed, failed, skipped, unavailable and review-required evidence distinctly. Capability discovery suggests missing owners without mirroring source files. Test-layout observations preserve explicit/scoped policy and ask for unresolved conventions rather than asserting unsupported community consensus. Work registry absence, invalidity and supported version migration remain distinct from valid empty work.

Passing mechanical checks does not complete philosophy/ownership/stale-reasoning review. The skill supplies an actual semantic review; the deterministic CLI does not manufacture it. Unsupported/invalid inputs produce located findings, not success-shaped fallback defaults.

## Repairs and provenance

Report findings first, then offer an exact preview. Initial repairs restore available exact pinned asset bytes, compose explicitly owned generated blocks, rebase selected links from an accepted map and run supported work-schema migration. Custom templates are preserved; unavailable pinned bytes are reported without substituting a different package version. Configuration/taxonomy migrations use their explicit versioned planners and aligned decisions.

Owned blocks reject injected/nested/overlapping delimiters. Same-file repairs compose before one hash-bound operation. Stale edits refuse; shared writers lock, journal and support recovery. Preview/decline/dry-run preserve target bytes. The CLI does not run detected target scripts or rewrite application semantics as autofix. AI-authored nondeterministic transformations warn with their actual source and retain that provenance through fixed-plan application.
