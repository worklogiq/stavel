## Behavior and compatibility

Bare init discovers a project boundary, asks when valid roots compete, gathers decisions through terminal or agent/headless interfaces and shows the actual configuration/product facts before alignment. Explicit target/name/track/answers and configuration-home controls remain available. Existing complete name/answers automation retains its compatibility adapter; preview and dry-run never apply it. New guided setup uses committed directory configuration by default. Source-package assets stay independent of target policy.

Versioned sessions live outside the target in a per-user cache, retain decision sources until explicit cleanup and bind to target/source/catalog hashes. Corrupt, concurrent or stale sessions refuse; cached package defaults cannot become fake standing repository choices. Headless unresolved input is structured and exits 2 without waiting.

## Generated owners and effects

After actual alignment, the hash-bound preview seeds portable assets, editable story template, product-root overview and empty pointer registry without inventing future capabilities or active work. Existing canonical overview/template paths and edits are preserved. Missing audience/scope/outcome facts are questions. For existing root instructions, a reviewed owned routing block preserves their body and uses actual planned manifest entrypoints; it never links a nonexistent companion on repeat.

Application uses shared containment/preconditions/locks/journals and then runs packaged verification. Applied bytes with failed verification return applied-with-findings. Detected project scripts are not executed. Semantic acceptance remains distinct from generation and structural checks.
