## Contract and evidence boundary

Acceptance for the [requirements](./guided-workflows.requirements.md) and [design](./guided-workflows.design.md). These scenarios remain planned except where bounded test-placement, mode-help or story-template evidence is explicitly linked; they are not a claim that the entire feature suite ran. The existing 67-test baseline does not prove any newly proposed command, extension resolver or agent workflow.

Use existing Node/TypeScript tests and representative temporary filesystems. Exercise the actual built CLI through process boundaries; use controlled terminal input for interactive tests and a documented manual terminal pass where automation cannot establish usability. Avoid a new browser application or runner for this CLI feature.

## Independent agent trial

After implementation, give a fresh agent the relocated export and a scratch repository with accepted requirements, unrelated user work and a two-stage defining mechanism. Supply a task-only omission and a standing addition, then ask it to design, plan, execute a ready slice and close the PR-sized scope. Seed a stale amendment or missing required check. Assess actual reads, produced docs, diff, command results, preserved mechanism and reported gaps. Use a separate reviewer when authorized; self-assessment alone is supporting evidence.

Include actual design-review evidence or a scoped exception under the selected policy, and stop after one completed code-delivery slice before any future slice is implemented. Verify that declared endpoint independently; verify the broader integrated outcome separately. This distinguishes a coherent increment from an intermediate broken branch that only becomes usable after the whole plan.

Also perform the T-24 through T-27 workflow trials with incremental planning, an execution request requiring preparation, conflicting selected plans and interrupted VIBE iteration. Assess which decisions were actually recorded before interruption and whether the next agent can resume from owner records. Use real observed actions to distinguish mode routing and fidelity from matching prompt text.

Record baseline/source/artifact versions, inputs, exact command outcomes and durable references suitable for the repository's audience. Exported prompt presence does not establish correct model use. This is a conformance trial, not a claim of benchmarked agent reliability.

## Commands and delivery evidence

For implementation changes run npm test and npm run check, plus focused cases above. Use npm pack --dry-run, an actual offline packed-package install and relocated export at distribution boundaries; follow the existing Node/Windows/Linux CI support matrix. Run additional commands only where relevant and authorized. This drafting task does not publish, push or mutate CI.

When a slice closes, add requirement-to-implementation-to-evidence results to its canonical result section or a linked verification record. Include failures, skipped coverage and known limitations. Archive completed delivery evidence only after the scoped acceptance is actually met.
